# 🔎 OsintX

**Реальный OSINT-комбайн по открытым источникам.** Ищет человека и его цифровые следы по email,
логину, телефону, Telegram, домену, IP, ФИО и криптоадресам. Каждая находка подтверждена
доказательством (URL, HTTP-код, фрагмент ответа). Никаких выдуманных данных.

Работает в трёх режимах:

| Режим | Команда | Что это |
|---|---|---|
| 🖥 **Web-приложение** | `osintx serve` | Форма поиска, живые результаты по SSE, отчёты, история, загрузка своих баз |
| ⌨️ **CLI** | `osintx search <цель>` | Полноценный терминальный поиск с прогрессом и отчётами в 8 форматах |
| 🤖 **Telegram-бот** | `osintx bot` | Поиск прямо в Telegram: `/search`, `/deep`, `/id`, файлы отчётов кнопками |

**Быстрый старт бота:**

```bash
./start_bot.sh          # Linux/macOS: окружение + зависимости + мастер настройки + запуск
start_bot.bat           # Windows — то же самое

# или вручную:
pip install -r requirements.txt
python bot.py --init    # мастер: спросит токен и проверит его
python bot.py           # запуск бота
```

Подробная инструкция и разбор типичных проблем — в [QUICKSTART.md](QUICKSTART.md).

## ⚖️ Главный принцип: честность результата

Большинство «OSINT-ботов» и «пробивов» показывают выдуманные данные. OsintX так не делает:

* **Находка появляется только при положительном доказательстве** — код ответа, строка в теле,
  значение в JSON, запись в DNS. В отчёте рядом с каждой находкой стоит поле `доказательство`.
* **Недоступный источник — это `error`/`blocked`, а не «не найдено».** Отчёт всегда содержит
  блок покрытия: сколько источников проверено, сколько ответило, какой процент покрытия.
* **У каждой находки есть уровень достоверности** (`high`/`medium`/`low`) и, при калибровке,
  пометка «источник врёт → нужна ручная проверка».
* **Автоматическая калибровка источников.** Перед проверкой цели движок проверяет сам источник на
  заведомо существующем и заведомо несуществующем логине. Если сайт отвечает «найдено» на всё
  (типичный пример — PyPI, который отдаёт HTTP 200 с челленджем на любой адрес), источник
  помечается ненадёжным, и его результаты понижаются до `low`.
* **Ссылки на поисковики — это `link`, а не «находка».** Dorks (Google/Yandex с операторами) выводятся
  отдельным типом с `confidence=low` и честной пометкой «ручная проверка».

| **ВКонтакте** | `vk` | **реальная проверка VK**: с `VK_TOKEN` — официальный API (короткое имя, город/страна, дата рождения, статус, «о себе», подписчики, сайт, верификация, карьера/образование, последний визит; стена `wall.get` — посты с датами/просмотрами/лайками; сообщества `groups.getById` + их записи); без токена — публичная мобильная страница `m.vk.com/<логин>` (имя, записи, даты); капча помечается как `blocked`, а не «не найдено» |
| **MAX** | `max` | **мессенджер MAX** (`max.ru`): канал/бот по `@нику` (`max.ru/@nick`), персональная ссылка на профиль `max.ru/u/<hash>`; честно фиксирует, что у личных профилей MAX нет публичных @username (люди ищутся только по персональной ссылке) — это помечается как `unsupported`, а не «не найдено» |
| **история** | `wayback` | **Как менялся ник/имя**: список снимков страницы в веб-архиве (CDX), сравнение ранних и позднего снимков `t.me/<логин>`/сайта — прежние имена, описания, годы активности; плюс локальная история: каждое поле профиля сохраняется в базу, и `/changes` показывает, что изменилось между проверками |

**Движение по цепочке.** Поиск не заканчивается на одном модуле: из email автоматически
извлекается локальная часть — она проверяется как логин по всем 214 площадкам реестра и как Telegram-профиль,
а домен адреса уходит в доменный модуль (DNS, MX, SPF/DMARC, поддомены). Найден домен — тянутся
поддомены, IP и опубликованные на сайте адреса; найден логин — проверяется Telegram и связанные адреса.

```
$ osintx search torvalds@gmail.com
  email     → torvalds@gmail.com   20 источников
  domain    → gmail.com            10 источников   (MX, SPF, DMARC, поддомены)
  telegram  → torvalds              4 источника
  username  → torvalds            169 источников   (GitHub API: реальный профиль)
```

**Где живёт и как менялся ник.** Два вопроса, ради которых всё и делается:

```bash
osintx geo torvalds            # 📍 Вероятное местоположение: Портленд, США
osintx changes torvalds        # что изменилось у цели с прошлых проверок
osintx search torvalds -m username --no-save   # в отчёте — блоки GEO / IDENTITY / HISTORY
```

* **Местоположение** собирается только из публичных данных: поле `location` в профиле GitHub/GitLab,
  Gravatar-профиль (там люди сами указывают город), Keybase, Steam, bio в Telegram, страна номера
  телефона, тексты найденных сайтов. Каждое утверждение в отчёте подписано: источник, ссылка и
  фрагмент текста, из которого сделан вывод («доказательство»). Итоговый вывод — голосование:
  сколько источников подтверждают страну/город, столько и доверия; расхождения видны в `alternatives`.
* **История ников и имён** берётся из двух реальных источников: (1) снимки веб-архива за разные годы —
  сравнение `og:title`/`og:description` показывает, что профиль назывался иначе; (2) собственная база:
  при каждом поиске сохраняются публичные поля (ник, имя, био, город, подписчики), поэтому `/changes`
  и `osintx changes` показывают «было → стало» с датой наблюдения.
  Страна номера — **не** доказательство проживания, и это прямо написано в отчёте.

**Где писал: Telegram, ВКонтакте, MAX.** Второй пласт «где человек оставил следы» — его публичные
сообщения и площадки, где он ведёт аккаунт:

```bash
osintx search @durov                # в отчёте: t.me:activity (период, частота, свежие посты)
                                    #            t.me:search(...) — посты, где встречается логин/почта
osintx search durov -m vk           # ВКонтакте: профиль, город, записи (+ VK_TOKEN → полный API)
osintx search durov -m max          # MAX: канал/бот по нику; ссылка max.ru/u/… — существование профиля
```

* **Telegram без MTProto** уже даёт «где писал»: страница `t.me/s/<канал>` разбирается в посты
  (текст, дата, ссылка), считается период активности и частота, а параметр `?q=` ищет конкретные
  посты с упоминанием логина, имени или email — со ссылками на сообщения.
* **ВКонтакте** парсится и без ключей: `m.vk.com/<логин>` отдаёт имя, записи и даты; сервисный
  ключ `VK_TOKEN` (бесплатный, 1 минута в настройках приложения) включает официальный API —
  город, подписчиков, статус, сообщества, точные даты и просмотры.
* **MAX** — только то, что реально публично: каналы и боты по `@нику` и персональные ссылки
  `max.ru/u/<hash>`. Публичного поиска людей там нет, и модуль это прямо сообщает.
* **Что чаще всего пишет.** По реальным текстам сообщений считается топ слов (без служебных),
  хэштеги, домены ссылок, средняя длина, язык и активные часы — это видно в находке `t.me:topics`
  / `mtproto:topics`.
* **Где был и где писал.** `mtproto:chats` — открытые чаты и каналы, где найдены его сообщения
  (сколько и с какими ссылками); `mtproto:common-chats` — **общие группы с вашим аккаунтом**
  (`GetCommonChats`). Полные списки групп аккаунта Telegram публично не отдаёт: без MTProto модуль
  честно пишет `unsupported` и объясняет, что именно можно увидеть с ключами my.telegram.org.

**Прежние юзернеймы — даже без запущенного бота.** Каждый поиск сохраняет увиденные ники в локальную
базу, поэтому история имён остаётся доступной всегда и офлайн:

```bash
osintx usernames durov      # текущий ник + все прежние, с датами наблюдений и источниками
osintx changes durov        # там же: что менялось (ник, имя, био, город)
```

Поиск различает ники из `t.me` и из MTProto (`users.GetFullUser` → `usernames`), объединяет их
по аккаунту и запоминает: в инсайтах отчёта появляется строка «🏷 Юзернеймы: @current · ранее: @old»,
в боте — `/usernames <цель>` (читает только локальную базу, сеть не нужна).

**Связывание данных (граф).** Каждый поиск строит граф сущностей и связей
(`email → аккаунт`, `логин → криптоподтверждённый профиль`, `домен → IP`, `телефон → Telegram`).
Граф хранится в SQLite и экспортируется в Mermaid/DOT.

## 🚀 Установка

```bash
git clone <repo> && cd Osint
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt      # зависимости
pip install -e .                     # ← создаёт команду `osintx` в PATH
cp .env.example .env                 # опционально: ключи API, токен бота   (Windows: copy)
```

Минимум для работы: `httpx`, `phonenumbers`, `dnspython`, `rich`, `fastapi`, `uvicorn`, `jinja2`.
Telethon нужен только для MTProto-модуля Telegram, `python-telegram-bot` — только для бота.

**Если команда `osintx` не находится** («не является внутренней или внешней командой»),
есть три равнозначных способа — выбирайте любой, всё делает одно и то же:

```bash
pip install -e .              # 1) установить проект (появится команда osintx; venv должен быть активен)
python -m osintx search durov # 2) то же самое без установки — модулем
python bot.py cli search durov  # 3) через бот-скрипт:  python bot.py cli <любая команда osintx>
```

На Windows удобно `osintx.bat` из корня проекта — он сам подхватывает `.venv\Scripts\python.exe`
и понимает те же аргументы: `osintx.bat tgauth`, `osintx.bat usernames durov`.

Проверка окружения (любой из вариантов выше):

```bash
osintx doctor
python -m osintx doctor
```

Команда покажет, что установлено, какие ключи заданы и **какие источники реально доступны из вашей сети**.

### Если pip не может скачать пакеты

`python-telegram-bot` не требует дополнительных пакетов: если `pip` споткнулся на
`apscheduler` или другом пакете, это почти всегда сбой DNS/сети, а не программы.

```bash
pip install -r requirements.txt        # повторить после смены DNS (см. ниже)
python bot.py --net                    # диагностика: DNS, TCP, TLS, прокси
```

Мастер настройки сам создаёт виртуальное окружение и ставит зависимости:
`python bot.py --init`.

### Если бот пишет «DNS», «getaddrinfo failed» или «ConnectError»

Это ошибка сети, а не кода: система не смогла получить IP-адрес `api.telegram.org`.
Проверка и лечение (по шагам):

```bat
python bot.py --net                    :: полная диагностика сети
nslookup api.telegram.org              :: должен вернуть IP-адреса
nslookup api.telegram.org 8.8.8.8      :: если так работает — виноват DNS провайдера
ipconfig /flushdns                     :: сбросить кэш DNS
```

1. **Смените DNS** (самый частый фикс): Параметры → Сеть и Интернет → Изменить свойства
   адаптера → IPv4 → Свойства → «Использовать следующие адреса DNS-серверов»:
   `8.8.8.8` и `1.1.1.1`.
2. **Прокси/VPN.** Многие клиенты поднимают локальный SOCKS-прокси — впишите его в `.env`:

   ```ini
   TELEGRAM_PROXY=socks5://127.0.0.1:1080   # прокси только для бота
   OSINTX_PROXY=socks5://127.0.0.1:1080     # и для самого поиска (источники)
   ```

   Для SOCKS нужен пакет: `pip install socksio` (он уже в `requirements.txt`).
   Если socks не работает — подойдёт HTTP-прокси: `TELEGRAM_PROXY=http://host:port`.
3. **Запустите бота там, где Telegram доступен** (VPS в другой стране) — Telegram API
   должен быть доступен из сети бота, иначе он не получит сообщения.

Проверка после настройки: `python bot.py --check` (реальный запрос к Telegram).

## 🖥 Веб-приложение

```bash
osintx serve                 # http://0.0.0.0:8000
osintx serve --port 9000 --reload
```

Что внутри:

* форма поиска с примерами, режимами (глубокий / варианты / SMTP / API-ключи);
* **живой прогресс по SSE** — видно, как находятся данные в реальном времени;
* страница отчёта с находками, доказательствами, сущностями, связями и покрытием источников;
* скачивание отчёта в JSON / HTML / Markdown / CSV / TXT / Mermaid;
* история поисков из SQLite;
* **загрузка внешних баз** (CSV/JSON/TXT) прямо в браузере → они попадают в FTS-индекс и
  проверяются автоматически;
* реестр источников `/sources` и Swagger `/docs`.

API:

```
POST /api/search              {"target": "...", "deep": false, "variants": false}
GET  /api/stream/{job_id}     прогресс (SSE)
GET  /api/report/{job_id}     результат (JSON)
GET  /report/{search_id}      HTML-страница отчёта
GET  /report/{search_id}/download?fmt=json|html|md|csv|txt|mermaid|dot
GET  /api/history, /api/stats, /api/sources, /api/graph, /api/meta, /api/health
POST /api/datasets            загрузка базы (multipart)
GET  /api/datasets/search?value=...
```

## ⌨️ CLI

```bash
# базовый поиск
osintx search ivan.petrov@example.com

# глубокий поиск с вариантами и отчётами во всех форматах
osintx search torvalds --deep --variants --json-out r.json --html-out r.html --md-out r.md

# конкретные модули и подробный вывод по каждому источнику
osintx search example.com -m domain --verbose

# где живёт: страна/город по публичным профилям (Gravatar/Keybase/Steam/Telegram/телефон)
osintx geo torvalds
osintx geo ivan@example.com --deep        # + веб-архив и логин-площадки

# как менялся ник/имя/био: что изменилось с прошлых проверок (локальная история)
osintx changes torvalds
osintx changes torvalds -n 50

# все ники цели: текущий и прежние — офлайн, из локальной базы (бот может быть выключен)
osintx usernames torvalds

# поиск по ФИО
osintx search "Иван Петров" -m person --deep

# сохранить и открыть HTML-отчёт
osintx search @durov --html-out durov.html

# проверка пароля по утечкам (k-anonymity: наружу уходят только 5 символов хеша)
osintx password 'qwerty123'

# свои базы данных: CSV/JSON/TXT → локальный FTS-индекс
osintx dataset-import dump.csv --name mydump
osintx dataset-search user@example.com
osintx dataset-list

# история и база
osintx history -n 20
osintx show --target ivan.petrov@example.com
osintx stats
osintx graph torvalds --format mermaid

# наблюдение за целью: ищем новые находки между запусками
osintx watch add ivan.petrov@example.com
osintx watch check

# реестр источников
osintx sources --category username --tags social
osintx sources --stats

# «1000 соцсетей»: подключить публичные датасеты площадок (≈700 + ≈400 сайтов)
osintx sources --import-wmn                    # WhatsMyName (CC BY-SA 4.0), скачает и добавит в реестр
osintx sources --import-wmn wmn-data.json      # из локального файла (если сеть блокирует загрузку)
osintx sources --import-sherlock               # Sherlock (MIT)
osintx sources --import-clear                  # убрать импортированные площадки
```

Полезные флаги: `--deep` (больше источников), `--variants` (варианты написания),
`--smtp` (проверка существования ящика), `--no-keys` (без API-ключей),
`--no-calibrate` (быстрее, но возможны ложные срабатывания),
`--max-sites N`, `--timeout`, `--out FILE --format html`.

## 🤖 Telegram-бот

### 1. Получите токен
Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → имя и юзернейм бота.
Токен выглядит так: `123456789:AAH...`.

### 2. Настройте одной командой

```bash
osintx init      # мастер: спросит токен, проверит его через getMe, сохранит в .env
```

Или впишите вручную в `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456789:AAH...
TELEGRAM_ALLOWED_IDS=          # свой ID (узнать: напишите боту /start — он ответит),
                               # пусто = бот открыт для всех
WEB_PUBLIC_URL=https://ваш-домен   # необязательно: кнопка «Открыть веб-отчёт»
```

### 3. Проверьте и запустите

```bash
osintx bot --check      # реальная проверка токена через getMe + отчёт о настройках
osintx bot              # запуск (Ctrl+C — остановить)
```

Либо скриптами из корня проекта: `./start_bot.sh` (Linux/macOS) и `start_bot.bat` (Windows) —
они сами создают окружение, ставят зависимости, при отсутствии `.env` запускают мастер и
стартуют бота.

```bash
python bot.py --check     # то же самое, из корня проекта
python bot.py --net       # диагностика сети: DNS / TCP / TLS / прокси
```

Если `--check` пишет про DNS или «Не удалось подключиться к Telegram» — смотрите раздел
[«Если бот пишет DNS/getaddrinfo failed»](#если-бот-пишет-dnsgetaddrinfo-failed-или-connecterror):
там пошаговое лечение (смена DNS, VPN/прокси, проверка через `nslookup`).
Прокси задаётся одной строкой в `.env`: `TELEGRAM_PROXY=socks5://127.0.0.1:1080`
(а `OSINTX_PROXY` направит через прокси ещё и поиск по источникам).

### 4. Что умеет бот

**Поиск**

| Команда | Что делает |
|---|---|
| любой текст или `/search <цель>` | полный поиск (email, логин, @telegram, телефон, домен, IP, ФИО, крипта) |
| `/deep <цель>` | глубокий поиск: больше источников, варианты написания |
| `/email` `/user` `/phone` `/tg` `/domain` `/ip` `/name` | быстрый поиск конкретного типа данных |
| `/geo <цель>` | **где живёт**: страна/город из публичных профилей (GitHub, Gravatar, Keybase, Steam, bio Telegram, страна телефона) |
| `/changes <цель>` | **как менялся ник/имя/био/город** — сравнение с прошлыми проверками цели |
| `/usernames <цель>` | **все юзернеймы цели**: текущий и прежние — читается из локальной базы, работает офлайн |
| `/vk <ник>` | **ВКонтакте**: профиль, город/страна, подписчики, публичные записи, сообщества (без `VK_TOKEN` — публичная мобильная версия) |
| `/max <ник\|ссылка>` | **мессенджер MAX**: канал/бот по `@нику`, персональная ссылка `max.ru/u/…` |
| `/id <@username\|телефон>` | Telegram-разведка: карточка t.me, подписчики, посты, fragment; **«где писал»** — активность, топ слов/хэштегов, чаты с его сообщениями; с MTProto — ID, DC, **общие группы** (`GetCommonChats`), глобальный поиск по сообщениям |
| `/cancel` | остановить текущий поиск |

**Работа с результатом** — кнопками под сводкой:

* 🔗 **пивоты** — «раскрутить дальше»: нажмите на найденный email, логин, домен, IP или телефон-цель,
  и бот запустит новый поиск по этой сущности (email → его домен и логин, логин → Telegram и т.д.);
* ◀ ▶ **пагинация** — находок бывает десятки, сводка листается постранично;
* 📄 HTML · 🧾 JSON · 📊 CSV — файл отчёта;
* 🧠 Глубже — повторный глубокий поиск по той же цели;
* 📈 Граф — связи сущностей (mermaid);
* 🌍 Веб-отчёт — открыть полный отчёт в веб-приложении (нужен `WEB_PUBLIC_URL`).

**Наблюдение и сервис**

| Команда | Что делает |
|---|---|
| `/watch add <цель>` `/list` `/check` `/rm` | слежение за целью: бот сравнивает находки между проверками и пишет **только о новых** |
| — | фоновая автопроверка наблюдений каждые `TELEGRAM_WATCH_INTERVAL` часов (по умолчанию 6) |
| `/settings` | настройки: глубокий режим, варианты, ключи, сохранение в историю — кнопками |
| `/modules` | выбрать модули кнопками (или `/modules email ip domain`) |
| `/report <id>` | заново получить отчёт из истории (пагинация и кнопки работают) |
| `/password <пароль>` | проверка пароля по утечкам (k-anonymity — пароль никуда не уходит, сообщение удаляется) |
| `/history` `/stats` `/sources` `/graph` `/dataset-search` | история, статистика, источники, граф, поиск по своим базам |

**Защита от перегрузки:** на пользователя действует лимит — `TELEGRAM_SEARCH_COOLDOWN` секунд между
поисками (по умолчанию 8) и `TELEGRAM_MAX_PER_HOUR` поисков в час (40). Бот отказывается запускать
второй поиск в том же чате одновременно.

### 6. MTProto: числовой ID, DC, общие группы и глобальный поиск по сообщениям

```bash
# 1) api_id/api_hash на https://my.telegram.org → API development tools (бесплатно, 1 минута)
#    в .env:  TG_API_ID=1234567   TG_API_HASH=abcdef0123456789
osintx tgauth        # одноразовый вход — ТОЛЬКО в терминале на вашем ПК, не в чате бота
python bot.py tgauth # то же самое, если команда osintx не в PATH
osintx bot           # после входа /id отдаёт ID, DC, общие группы и поиск по сообщениям
```

Что спросит `osintx tgauth` (то же самое: `osintx tg-auth`, `python -m osintx.tg_auth`):

1. **номер телефона** в международном формате (`+79991234567`);
2. **код из Telegram** — приходит сообщением в сам Telegram (не по SMS), живёт пару минут;
3. **пароль 2FA** — только если он у вас включён.

Файл сессии появится рядом с базой: `$OSINTX_DATA_DIR/<TG_SESSION>.session`
(по умолчанию `.osintx-data/osintx.session`). Сессия = вход в ваш аккаунт: не передавайте её
третьим лицам, отозвать можно в Telegram → Настройки → Устройства.

**Если Telegram блокируется сетью** — тот же прокси, что и у бота:

```bash
TELEGRAM_PROXY=socks5://127.0.0.1:1080      # или http://user:pass@host:port
pip install "python-socks[asyncio]"         # Telethon требует этот пакет для любого прокси
osintx tgauth
```

Без MTProto **числовой ID не вычисляется**: публично его взять негде, «генераторы ID по
юзернейму» — обман. OsintX честно помечает такие пункты как `unsupported`.

**Что даёт вход:** числовой ID и access_hash, DC, дата регистрации, bio целиком, юзернеймы
аккаунта (для истории ников), **общие группы с вашим аккаунтом** (`GetCommonChats`) и чаты, где
человек писал (глобальный поиск) — то есть «в каких группах был и где писал» из раздела выше.

### 7. Как доработать бота под себя

Бот запускается корневым файлом `bot.py` (удобная обёртка: проверяет зависимости, умеет
`--init`, `--check`, `--token`). Логика — в пакете `osintx/netcheck.py         # диагностика сети: DNS/TCP/TLS/прокси (--net, osintx net)
osintx/bot/`:

```
bot.py                  # python bot.py / --init / --check / --token
osintx/bot/
├── run.py              # команды и обработчики (по одной функции на команду)
├── ui.py               # клавиатуры, сводка с пагинацией, пивот-кнопки, память отчётов
├── watch.py            # наблюдение: снимки находок и поиск новых
└── limits.py           # лимиты частоты поисков
```

Каждая команда — функция `async def cmd_*(update, context)`, которая регистрируется в
`build_application()`:

```python
async def cmd_ip(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    """Пассивный IP: адрес и ASN без полного поиска."""
    ip = " ".join(context.args).strip()
    if not ip:
        await update.message.reply_text("Использование: /ip 8.8.8.8")
        return
    await run_search(update, ip)          # та же механика, что у /search

# в build_application() рядом с остальными:
app.add_handler(CommandHandler("ip", cmd_ip))
```

Готовые точки расширения UI: `ui.report_keyboard()` (кнопки под сводкой), `ui.pivot_targets()`
(что предлагать раскрутить), `ui.summary_text()` (постраничная сводка), `cmd_callback()`
(обработка нажатий по префиксам `dl:` `page:` `pivot:` `graph:` `mod:` `set:`).

Полезные точки расширения:

* `run_search()` — общая логика с прогрессом, клавиатурой и файлами отчётов;
* `_report_keyboard()` — добавьте свои кнопки в `cmd_callback` (обработчик `data.startswith(...)`);
* `Progress` — редактируемое сообщение прогресса (порог обновления 1.6 с, чтобы не упереться в лимиты Telegram);
* `Engine().search(..., on_event=...)` — любые свои события можно вешать на тот же поток.

Свой бот на другом фреймворке (aiogram и т.п.) — просто вызывайте движок напрямую:

```python
from osintx.report import to_html
from osintx.engine import Engine

report = await Engine().search(target, deep=True, on_event=my_progress)
open("report.html", "w").write(to_html(report))
```

Для кнопки «Открыть в веб-приложении» задайте `WEB_PUBLIC_URL` и добавьте инлайн-кнопку
`WebAppInfo(url=...)` — бот уже передаёт ваш ID в `settings.public_url`.

## 🧱 Расширение без правки кода

**Свой источник** — файл `$OSINTX_DATA_DIR/sites_user.json`:

```json
{
  "username": [
    {"name": "my-forum", "url": "https://forum.example.com/u/{username}",
     "strategy": "status_code", "found_codes": [200], "not_found_codes": [404],
     "confidence": "medium", "kind": "profile", "tags": ["forum"]}
  ]
}
```

Пользовательские источники объединяются с базовыми (по имени) и проверяются в каждом поиске.

**Публичные датасеты площадок** — самый быстрый способ получить «1000 соцсетей»: OsintX конвертирует
чужой формат в свой и кладёт в тот же `sites_user.json` (базовые файлы не меняются, датасет можно
удалить одной командой):

```bash
osintx sources --import-wmn                 # WhatsMyName ≈700 площадок (CC BY-SA 4.0)
osintx sources --import-sherlock            # Sherlock ≈400 площадок (MIT)
osintx sources --import-wmn путь/к/data.json  # из локального файла (когда сеть блокирует загрузку)
osintx sources --import-clear               # отключить импортированное
```

Правила «найден/не найден» переносятся как есть, записи получают теги `wmn`/`sherlock` (можно
фильтровать: `osintx sources --tags wmn`) и пониженное доверие — датасетные площадки стоит
использовать вместе с калибровкой, которая отсеивает сайты-обманки.

**Системный реестр** собирается скриптом — списки источников лежат прямо в нём:

```bash
python tools/build_registry.py     # пересобирает osintx/data/sites_*.json
```

Стратегии проверки: `status_code`, `message_exclude`, `message_include`, `json_path` (с операторами
`exists/equals/not_equals/contains/empty`), `regex`, `redirect`, `unsupported`.
Поддерживаются `params`, `payload`, `json_body`, свои заголовки, таймауты и ретраи.

**Своя база данных** — `osintx dataset-import <файл>`; принимает CSV с заголовками (колонка
определяется автоматически или флагом `--column`), JSON-массивы и простые списки. Импортированные
значения ищутся в каждом поиске (источник `local-datasets`) и вручную: `dataset-search`.

## 🗄 Хранение данных

Всё складывается в `$OSINTX_DATA_DIR` (по умолчанию `.osintx-data/`):

* `osintx.db` — SQLite (WAL): поиски, находки, сущности, связи, здоровье источников, watchlist,
  импортированные базы (FTS5), кэш;
* `reports/` — сохранённые отчёты;
* `uploads/` — загруженные внешние базы;
* `*.session` — MTProto-сессия Telegram (не публикуйте её!).

## ⚠️ Ограничения — честно

* **Публичные источники и только они.** Никаких «пробивов» по закрытым базам, доступа к чужим
  аккаунтам, обхода авторизации или использования украденных данных. Это законно и осознанно.
* **Сайты блокируют ботов.** Instagram, Twitter/X, LinkedIn, Cloudflare-защищённые сайты часто
  отдают капчу или 403. OsintX показывает это как `blocked`, а не как «не найдено». Решение:
  запуск с домашнего/мобильного IP или через `OSINTX_PROXY`.
* **Совпадение ≠ личность.** Занятый логин `ivan` не значит, что это тот самый Иван. Именно поэтому
  у каждой находки есть уровень достоверности и пометки о необходимости ручной проверки.
* **Числовой Telegram ID без MTProto недоступен.** Точка.
* **Список групп аккаунта — приватные данные.** Telegram не показывает, где именно состоит человек:
  публично видны только чаты/каналы, где найдены его сообщения, а общие группы — лишь при
  авторизованной сессии MTProto (`GetCommonChats`). Модуль так и пишет — `unsupported`, а не «не найдено».
* **VK и MAX без ключей дают не всё.** ВКонтакте без `VK_TOKEN` может показать капчу (в отчёте —
  статус `blocked`), а у личных профилей MAX нет публичных `@username` вообще: модуль проверяет
  каналы/ботов и персональные ссылки и честно помечает остальное как `unsupported`.
* **Датасетные площадки требуют калибровки.** После `--import-wmn`/`--import-sherlock` реестр
  становится очень широким, но правила чужих датасетов не проверены нами: смотрите на калибровку
  и уровень доверия, а сомнительные сайты отключайте тегом `disabled` в `sites_user.json`.
* **Данные устаревают.** Провайдеры меняют ответы; реестр источников нужно периодически
  перепроверять (`osintx doctor`, калибровка в каждом поиске).

## 🛡 Этика и закон

Используйте инструмент только в законных целях: проверка собственной цифровой экспозиции,
due diligence, журналистские расследования, корпоративная безопасность, CTF/обучение.
Обработка персональных данных в большинстве юрисдикций регулируется законом (GDPR, 152-ФЗ и др.) —
ответственность за использование лежит на вас. Не преследуйте людей.
